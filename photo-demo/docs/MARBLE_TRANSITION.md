## 第一人称漫步

在实景页点击「工位漫步」，或在背面的群岛全景点击「上岛漫步」。可在五座岛与桌下海底之间选择步行地点，WASD / 方向键移动，拖动或用 IJKL 环顾。触屏可以一指按住方向键、另一指拖动。Esc 或「返回群岛」回到原机位。洞窟的「走进书屋」衔接原有的门、书桌和书页互动。

脚下、墙壁、栏杆及顶面的检测来自同一套入水配准后的网格。工位使用 Marble 附带的碰撞网格。首次进入一个地点时在后台建立空间索引，之后复用。橙书已重建跨谷木桥、东端石岸前的踏步、旅舍百叶窗与橄榄树冠。蓝杯登岸的砖阶、白崖和潮港的系缆件亦随高清模型构建。运行 `npm run check:island-walk` 验证键盘、触控、上下阶和书屋衔接。

洞窟的下层石梯通过三段折返木梯接到上层露台。梯板、扶手、立柱和支撑参与碰撞，原栏杆在木梯抵达的位置切出了入口。开口参数保存在 `scripts/grotto-bookroom.json`，全尺寸外壳和回退模型均需保留这处开口。步行检查还会从石岸连续走过全部梯段与平台，抵达绿门前。

## 跟随故事

主桌面画面上方的「跟随故事」从工位出发，依次前往蓝杯港湾、蓝书白崖、橙书峡谷、手机潮港和洞窟书屋。反复点击同一个按钮即可体验各站：自己折船、把它推出去，再从白崖的镜筒里看见它。也可以直接在场景里动手，按钮会跟着当前进度变化。最后一次点击会穿过书页，回到最初的工位。途中可「退出导览」，在当前位置继续自由体验。

点击「下一站」后，镜头从当前近景退到岸外，沿海面连续移动到下一站的互动位置。望远镜、书签和静音键在远景中就已就位。开启「减少动态」时，上一站的画面与下一站短暂叠化。

本地服务启动后，`npm run check:story-tour` 检查同一按钮的桌面键盘和模拟触屏全程、返回原机位、重游、加载失败重试和取消。

## 白崖、峡谷和潮港（2026-11-06）

主桌面在全景、自由浏览和故事模式中都默认使用高清模型。开始绕行时加载蓝书、橙书和手机的高清 GLB，每件约 32 万三角面，配 4K 颜色贴图；手机海岸接入机框时会裁去重叠的底座。电脑洞窟从第一帧起复用完整的开门外壳。蓝杯港湾、工位台灯、椅子与纸叠也使用高清模型；书屋里的书桌、座椅和书柜在入室前按需加载高清版。

到达群岛后，点选小岛或用「选择目的地」近看，再用画面左下角的入口进入故事。

- **白崖**：点黄铜望远镜进入目镜，向上拖动抬高视线，向下拖动压低视线，也可使用方向键。目镜下方的倍率滑杆从 1× 到 6×，每次调整 0.5×，入岛默认 2×。先来可以看过往帆船；在蓝杯放过船后，离岸的同一艘纸船还会沿白崖外的海流航行。
- **峡谷**：按住橙色书签向下压，再松手，织带兜成吊床，镜头躺进两侧岩壁之间。也可以用「压低书签」操作或随时坐起来。
- **潮港**：银色圆角机框、三摄背板与侧键共用同一片海岸。只降低港池床面，动态海水通入池内，栈桥和机框露出水面。镜头停稳后先留出约四分之三秒，工作群消息再弹出，水面随之映出通知。拨动侧键，工作群通知与水中倒影一起熄灭。可单独开启港湾环境声，静音后稍等片刻会听见绳索敲桅杆。离岛会收声；本次浏览中，侧键保留上次的位置。

Esc 或「返回群岛」回到来时的视角。「减少动态」保留每个手动动作。运行 `npm run check:island-stories` 可检查鼠标、模拟触屏、键盘、退出重访，以及纸船在目镜里的实际可见性。

## 蓝杯港湾的纸船（2026-11-06）

从群岛点蓝杯，或在目的地选「蓝杯 · 走到海滩」，镜头会从杯沿降到小屋前的浅滩。点那张写着“这个需求今天能改完吗？”的纸条折船，按住船身向海面推，松手让它漂走。船抵达远水后，岸边出现“至少在这里，你可以下班了。”折船和推船也支持键盘操作。随时按 Esc 或点「返回群岛」可回到来时的位置，重新进入可再折一次。

## 咖啡蒸汽与台灯日照（2026-11-06）

转到群岛后，咖啡液面上的细雾升起，沿着风向逐渐凝成低云。拖动长臂灯的灯头，或使用画布下方的「长臂台灯」滑杆，可以在 06:00 到 18:00 之间移动。灯夹留在桌沿，双连杆绕关节转动，灯罩的方向决定群岛阴影、海面高光和水下光束的位置。键盘聚焦滑杆后可用方向键微调，Home / End 直达日出和日落。「减少动态」冻结蒸汽和云的漂移，仍可手动调灯。

启动本地服务后，`npm run check:desk-weather` 检查鼠标和触屏拖灯、键盘调光、影子换向，以及固定镜头下蒸汽和云的可见性。

## 桌面海浪与桌下浅海（2026-11-06）

桌面在绕行 68°–132° 之间逐渐湿润。五组行进方向不同的波叠加在原桌面轮廓内；靠近桌沿和岛岸，浪高逐渐减小。桌下水体沿同一水位往下展开，镜头可以从侧面透过水体看见礁石，也可以从右上角的「选择目的地」潜到沙底。Q 下潜，E 上浮，「全景」回到群岛机位。

绕行进度决定海岸和水位，独立的海洋时钟驱动海浪、海底光纹、鱼群和海藻。停止移动镜头后水仍然流动；「减少动态」冻结当前海况，适合同机位对照。海底几何在水体展开时创建，鱼和植被采用实例绘制。海湾反光复用已有的场景颜色和深度。

海浪按桌面尺度实现。礁石、珊瑚和海藻造型改编自 ABYSSAL 的 ReefGeometry，水底光纹参考其 UnderwaterMaterial；来源版本与 MIT 许可随代码保存在 `dist/vendor/abyssal/`。[参考项目及对应版本](https://github.com/emollick/abyssal-living-deep/tree/ae30cdd1746e0fda2f01ccd2a4dd4cee047169a4)

启动本地服务后，运行 `npm run check:desk-ocean` 可验证固定机位的水面与水下像素变化、冻结与恢复、手动穿过水线和触屏尺寸下的往返。浏览器依赖沿用现有的 Marble 检查脚本。

## 历史：桌面成海，物件成岛（2026-11-04）

用户进一步授权：翻到背面后，整个桌面可以成为湖水/海水，独立物件成为小岛。本轮采用平静的青蓝海水。上一版完整保存于 `/marble-islands-before-sea/index.html`；该页不包含新的水材质。

- `desktop-sea.js` 在同一桌面网格上做材质变化，保留原来的四角、桌沿、支撑平面和白色侧边；没有额外覆盖层，也不扩展水域边界。电脑、书本、杯子的位置不变。
- 水面从68°开始、132°完成，沿桌面坐标从后沿向前逐步出现。法线波纹、粗糙度、颜色与原照保留量一起变化。水面属于桌面本身的变化；物件隐藏景观继续遵守固定源机位的遮挡容积。
- 从校准电脑底座、书封四边形和杯碟椭圆计算岸边距离，产生浅水颜色、细小岸边波纹与水底光斑。使用原有环境反射；没有新增模型或图片生成。

证据：`evidence/marble-desktop-sea/`。本次实际视口716×988，不冒充手机尺寸验收。没有commit/push，图片和大资产继续忽略。

## 历史：正面轮廓约束与电脑背板主景（2026-11-04）

用户明确：度假世界必须隐藏于原照片中物件的后方，不能从正面轮廓外露；电脑背板应该成为主要景观。调整前版本完整复制至 `/marble-transition-restored/index.html`；原主 demo、Marble/refined 和首版转场均保持原样。

- `hidden-world.js` 重新组织已有 `holiday-island.glb`、`holiday-house.glb`。电脑背板根据校准网格的背面四角建立局部基底，在大部分背板内放置分层小屋、阶梯、海港和浅海承托面。杯内保留完整海岛。书本小屋缩小并收至卷纸后方，移除高台、棕榈树和跨越空白桌面的水面/栈道。
- `objects.js` 暴露固定源机位的物件深度图。所有度假景观片元投影回原机位后，必须比物件深度至少远 1.5mm，并位于轮廓内缩约 1.5 源像素的范围中。该固定空间裁剪约束也用于发现遮罩；不随当前相机或进度变形。新增景观不向正面桌面投射影子，以免隐藏物件仍泄漏可见阴影。
- 取消景观本身22°–48°的透明渐入；景观始终以实体存在，通过当前视点下的深度遮挡逐步被发现。房间背景仍在52°–82°连续交接，镜头与原4.8秒路径不变。
- `auditSourceOcclusion` 在固定原始机位以660×870渲染建模场景，对比景观全部开启/关闭的beauty pass。当前 changedPixels=0、maxChannelDifference=0。结果保存在画布 `data-front-occlusion`，不经过转场渐隐。
- 浏览器检查0°、60°、135°、180°；最终0°/60°往返画布逐像素差为0，相机和投影相同，日志无错误或警告。三种画布比例各3601次镜头采样通过。证据：`evidence/marble-hidden-world/`。本次未新增窄屏实机验收，沿用既有响应式布局。

限制：隐藏保证针对**原照片机位**；绕行产生的显露是预期行为，不要求所有正面扇区都隐藏。源深度来自校准近似网格，固定空间裁剪可能影响超出容积的模型边缘，后续资产设计仍应优先完整容纳在遮挡空间内。整个外围房间的配准、源书上纸件的背面质量不在本轮修复范围内。没有新模型生成费用，没有commit或push。

## 如何体验

- 向左拖动画面或拖动进度条向后绕行，反向拖动返回。滚轮、方向键、Home、End 也可操作。
- 点击播放，从当前进度继续；终点点击播放会返回实景。暂停后水面、树叶与船一同固定，方便比较。
- 展开「同机位检查交界」，切换完整转场 / 仅实景 / 仅建模世界，并单独开关交界柔焦。版本切换保持相机和投影。
- 可用 `?progress=0.32` 等参数定位进度，范围为0–1。窄屏镜头保证主要物件的水平取景范围。

## 渲染与时间线

### 一份物件，一台相机

两个场景共用同一个 Three.js 相机以及同一组9个校准实体：电脑屏幕/底座、杯身/杯柄/咖啡/杯碟、书封/书页、Hi3D纸页。实体在两个离屏渲染过程中临时挂到各自场景，几何和变换保持不变。两侧都用固定源机位的原照材质和可见性约束，不同时显示两套独立拟合的电脑或杯子。

实景保留 refined SPZ 与原有桌面修补网格。建模侧使用完整桌面，原照四角射线落到同一支撑平面确定斜向布局；后沿和书本一侧增加承托区，支持创作出来的微缩海湾。该扩展不是对不可见桌面的真实恢复。

### 边绕行边交接

`journey.js` 将进度映射为0°–180°镜头、连续投影、交接权重和景观时间。先沿保留的近桌路径移动，再逐渐转为后侧观察机位；最终镜头实际位于物件后方。没有在某个角度重置相机或停住后切画面。

当前交接区间为28°–86°：空间背景通过窄混合边界交接，较宽的光学柔化区域衔接两侧。前景实体遮罩及邻域保护使电脑、杯子和书本保持清晰。柔焦使用纹理 mipmap 预滤波，没有稀疏大间距采样产生的多份边缘。区间是此案例的试验参数，不是通用最佳值。

照片着色器先把颜色解码到线性空间，与 Spark、PBR 景观在离屏缓冲中合成，最后做一次显示编码，避免同一个物件在换场景时突然变亮。后侧窗帘只使用原照无物件区域的固定投影，在65°–100°退场，为度假世界留出背景；此段不会继续补全原Marble房间。

水面、船和树叶的轻微变化由进度直接计算。暂停时静止，回程状态确定。阴影使用固定预热结果，未实现独立的实时天气、风或持续播放的海面动画。

## 本轮排错

| 问题 | 处理 |
| --- | --- |
| 后方镜头过近，小屋裁出画面 | 调整后方距离、焦点及分阶段镜头视角；窄屏加入水平取景下限 |
| 完整桌面像轴对齐方块，交界形状差异大 | 从原照桌面四角重新投影到支撑平面，保留斜向布局 |
| 局部支持网格或纹理边界在完整桌面上形成阶梯轮廓 | 局部支持层只保留在实景；建模桌面使用干净的中性颜色样本与接触阴影，不把旧补片边界复制进去 |
| 小门穿进电脑正面 | 由实际背板顶点建立局部基底，向后偏移并沿背板安放 |
| 窗帘贴图混进原照片的长臂灯 | 限定无物件的原照采样区，平滑过渡到中性背景 |
| 微缩海湾越过建模桌子边沿 | 增补后方和书本侧承托范围，保持度假物件位置固定 |
| Three.js 阴影配置警告 | 使用本机支持的 PCFShadowMap；预热并缓存静态阴影 |

## 边界与后续优化

目前背景从实景到建模的材质、桌沿和房间布局差异仍可辨认；柔化衔接并不等于照片级无痕转换。源杯口、书页及未见侧面的近似仍保留，纯实景模式大角度仍会暴露原3DGS空洞。模型侧补建支撑和度假世界是创作内容，未恢复完整实拍房间。

下一轮可根据实际体验微调交接角度、节奏、背景色温与景观细节；改动后重点复验交界停点及反向像素一致。当前先保留这条能逐帧检查的确定性路径。

## 代码和复现

`dist/marble-transition-lab/` 是独立静态源码目录：

- `journey.js`：纯进度函数、相机与投影。
- `objects.js`：保留版几何/纹理的加载与线性颜色输出，原文件未改动。
- `holiday.js`：共同支撑面、建模桌面、海岸/码头/步道及已有Hi3D小屋。
- `compositor.js`：两场景、共享物件遮罩、交界柔焦和最终颜色编码。
- `app.js`：加载、预热、可逆播放和交互；暂停后在短暂稳定期结束时停止重复绘制。

启动仍用 `npm run dev`，无需构建或API key。资产全部从现有 `marble-refined-lab/assets/`、`dist/assets/` 和 Spark 依赖加载；新克隆须按 [ASSETS.md](ASSETS.md) 恢复私有本地资产。

```sh
# photo-demo/ 下，离线相机与时间线检查
npm run check:marble-transition
```

此命令不发起生成、不打开浏览器，也不替代上述真实画面/交互检查。更完整的Marble流程和通用化边界见 [工作流参考](MARBLE_WORKFLOW_REFERENCE.md)。
