# 书页回到最初空间

主体验入口：`http://127.0.0.1:9988/marble-transition-lab/index.html`。独立资产审阅仍保留 `holiday-assets/bookroom.html`。

现在主桌面中的电脑背后已经是新版洞窟。点击播放或拖动绕到背后 → “走进洞窟书屋” → 相机沿海湾靠近二层露台 → 推门进入 → 走近桌上摊开的书 → 点击右页原图 → 放大并回到最初的 Marble 3DGS 机位。可以重复循环，也能从书桌原路退回露台和桌面群岛。

主流程共用一个 canvas、一个渲染器和同一台相机，外壳、室内、门与家具都实际放在桌面电脑的背后。群岛到露台没有页面跳转、iframe 或章节黑幕。书页到实景仍通过原始照片的同裁剪构图交接，以衔接照片与 Gaussian 重建的差异。

绕到 180° 后，可在蓝书白崖、橙书峡谷和手机潮港间自由移动。从任意观察位置进入书屋后，选择原路退出会回到刚才的位置和朝向。

## 主桌面的配准与导航

- `grotto-registration.js` 以主桌面真实电脑盖板的宽度、方向和倾角做等比配准，不压扁新景观；再按桌面水位校准前岸底座，避免海湾沉入桌面。
- `grotto.js` 在桌面使用洞窟远景。进入书屋时加载 `shell-grotto-v6.glb` 的精细洞窟和室内家具，电脑机身使用主场景的校准模型。室内的既有坐标变换再与桌面配准矩阵相乘，门轴、家具、取景、行走和书页共享这套变换。
- 杯内海岛沿用原机位的遮挡约束。完整洞窟不能沿用旧电脑小镇的容积裁剪，否则海湾和洞壁会被切掉；它随主场景的实景→建模交接显现，绿色深度蒙版只保护景观清晰度，不提前显露。起始实景通过包含完整洞窟的合成画面比较验证。
- `bookroom-visit.js` 驱动主相机：外部用连续曲线，室内用共享的门、家具避障路径；缩小 near 平面以支持微缩房间近距离观察，点光源功率随尺度调整。主入口停在门中心对应的露台，避开旧侧面观察位附近的栏杆。
- 回群岛前先走回固定露台点，再逆向飞回进入时的桌面机位。书页返回会重置到精确原始机位和投影，并关闭房门，供下次循环。WASD/方向键和触控方向按钮移动，拖动环顾，Esc 逐步退出。减少动态跳过长镜头。

## 书页与原件

- 构建时用向下射线采样 Tripo 书桌上摊开的两页书。运行时从 `page-surfaces.json` 读取 1,218 个顶点的高度，让右页照片和左页文字贴合原书弧度。
- 右页直接使用 `dist/assets/desk-original.jpg`，1320×1739。没有重绘或生成替代照片。
- 原图 SHA256：`a5a2ad89c596347fb97f38b9741b2d5e831f657cefa33b4150d7709c8d9365a0`。
- 书桌 GLB SHA256：`c9d8f42646681e4d1c0f366acd88f1de724d84f9d746e9f8bcd37866855cab8f`。
- 本轮未调用 Hi3D / Tripo 生成，没有新增建模积分消费。

## 书页交接与保留的独立审阅页

`bookroom-book.js` 负责贴页和世界坐标取景；`bookroom.js` 增加 `book`、`world` 两个阶段，靠近桌子仍通过原有避障路径。阅读结束恢复桌旁的行走机位。新版房屋的坐标变换同时用于相机朝向和 up 向量，保证俯看照片时方向正确。

`marble-transition-lab/journey.js` 导出的 `sourceCrop(aspect)` 同时决定书页放大终点、原图过渡层和原空间的投影裁剪。书页接近满屏后，短暂交接到同图的平面裁剪，再淡出显示已经准备好的真实 3DGS。重建画面本身与原照片有既有的重建差异，过渡不宣称逐像素相等。

以下 iframe 机制只适用于保留的独立 `bookroom.html` 审阅页，主桌面不使用它。`bookroom-portal.js` 只创建一个同源 iframe。走近书页时预载 `marble-transition-lab/index.html?portal=book`，收到首帧就绪后才允许进入；每次进入都回到原始机位。隐藏的 GS 暂停渲染；显示 GS 时书屋停止绘制。通过 origin、source 和请求编号检查消息，重复循环不会叠加 iframe。

载入失败或超时保留书页与离开书桌的操作，并提供重试；不会自动重新提交建模任务。iframe 消失或 WebGL 上下文丢失时不继续显示空白的“已进入”状态。减少动态模式跳过长镜头移动，同时传递给原空间播放器。

## 验证

`npm run check:bookroom-loop` 验证原文件哈希、5 种视口比例下的四角投影对齐、重复进入复用、错误来源消息、失败后重试、加载及准备超时。`npm run check:marble-transition` 验证既有转场镜头与反向时间线保持连续。

实际浏览器检查覆盖：正常动画进入、直接点击三维照片、两次完整循环、回到书页、离开阅读位、关门后自动开门退出、旧版 v3 阅读机位、390×844 视口及减少动态模式。窄屏无横向溢出；这属于桌面浏览器的移动视口检查，未测真实手机 GPU 性能。

截图与检查记录：`evidence/bookroom-loop/`。保留既有书屋导航脚本 `scripts/check-bookroom.mjs`；本轮新增的独立检查不要求启动浏览器。

## 主桌面接入的新增验证

`npm run check:desktop-bookroom` 验证等比配准/水位、房间与世界坐标往返、同一相机重复循环、门关闭时的通行限制、逆向退出、GS 准备失败后保留书页与退出、忙碌时拒绝重复动作。既有书页检查与 Marble 时间线检查继续通过。

可选网格检查：

```sh
node scripts/check-desktop-bookroom.mjs --export-path
blender -b --python scripts/check-desktop-bookroom-path.py
```

实际外壳 BVH 检查 1600 段接近路径：0 次穿模；最小距离约 0.00633（源模型坐标）。浏览器证据在 `evidence/desktop-bookroom/`，包括主桌面洞窟、室内、原图书页、返回实景及窄屏循环。起始合成画面开启/关闭完整洞窟比较为 0 个差异像素（1785×604）。浏览器正常动画、390×844 减少动态/直接照片点击两轮循环、室内关门后退出通过；返回相机矩阵与投影与初始值完全一致。窄屏无横向溢出，控制台无错误/警告。本机室内180帧中位8.3ms、P95 8.4ms；真实手机 GPU 尚未测试。
