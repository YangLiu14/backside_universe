# 可探索场景的画质制作与实机验收

把“接近 3A 游戏的质感”写成玩家可以亲眼验证的画面。鞋底小镇选了三种观察距离：站在桥上看街巷的纵深，站在檐下看前柜与后墙，走到井盖旁看瓦檐在水中移动。换一个题材，先找出它自己的这几种观看机会。[小镇实机复盘](SOLE_CITY_ENVIRONMENT_RESEARCH.md) · [可运行的作品简报](../cases/sole-city/story.json)

## 从参考到一段可玩的样板

1. **定参考和取景距离。** 用当地实拍定年代、尺度、铺装、店面和生活磨损；用目标游戏的实机帧分析光从哪边来、前中远景如何相互遮挡。开工时存下参考、主路线、最近可达距离、目标设备和输出尺寸。与用户约定过的帧时、预算及交付形式随作品保留。把需要复核的画面写入当前简报的 `artTargets`。
2. **用灰模走通，再做一段正式样板。** 选一条能远看、贴近、转身的短路。先搭出轮廓、地面、入口、楼梯和关键遮挡，用真实眼高从两个方向走一次。随后只为这段装上正式 Hi3D 模型、材质和灯光。留一条未用来摆景或调光的反向视线或支路，供扩建后复验。
3. **按缺陷选返修层。** 换角度就露馅的橱窗回到开口与内部网格；整个铺面一样亮，先看粗糙度和光源；远看清楚、近看糊，先查源像素和近景资源是否已加载。同类缺陷修进共用装配、材质或渲染规则，再抽查不同朝向的实例。缺少独特轮廓、真实进深或主体细节时，才为该件准备独立 Hi3D 输入。保留已合格资产、任务号与费用记录。
4. **扩展到全场。** 将样板中验证过的真实尺寸、材质通道、烘焙方法及精度切换应用到同类资产。转角、入口与远处天际线仍要按各自视线布置。用主路、预留路线和近景高负载处做冷启动与往返；按同一版本保存看片结论。agent 自主接续有证据的返修，用户已约定的方向审核及具体费用授权沿用原流程。

## 画质问题对应的制作动作

| 在实机里看什么 | 做到哪一层 | 怎样验 |
| --- | --- | --- |
| 从高处看去，空间有多深 | 摆前景遮挡、中段可辨地标和后排错开的轮廓。用不同体量、进退和转折塑造街区。 | 停在正常眼高，向前走并回望。看后排轮廓是否从近景边缘逐渐显露。 |
| 可贴近的店、桥和主体 | 有剪影、视差、接触或可通行要求的部件做实体。Hi3D 负责有辨识度的模型，装配处理开口、窗框、门槛、踏步及碰撞。重复构件可共享。 | 横移看前后遮挡，侧看边缘厚度；走上踏步，再从另一头下来。 |
| 各种表面受光时能否区分 | 让同一处修补、磨损或潮湿同时约束底色、粗糙度和局部凹凸。按实际尺寸分配整片色差、接缝和近看的细颗粒。 | 固定曝光，正看和斜看同一处表面。检查补丁边缘、湿岸与干地的过渡，以及金属、橡胶或水泥各自的高光。 |
| 暗处有细节，亮处仍有层次 | 先确定主光方向，再处理天光遮挡、接触阴影与局部反弹。固定建筑可烘焙；动态光影及视角相关反射按镜头需要实时计算。移动主要遮挡物后重烘受影响的区域。 | 用同机位对照檐额、后柜及室外一块参照墙。湿面在两处实站看同一个水坑，必要时仅在反射通道隐藏被映建筑，核对轮廓的来源。 |
| 原照片或材质近景是否糊 | 对照有效源像素、UV 覆盖和最大的屏幕占比。修复时对齐可辨认的沟槽、轮廓和配色，将生成补全的微纹理与实拍依据分别记录。 | 同一机位并排看全图和局部裁片。除清晰度外，核对配色、形变和动态交接。 |
| 人物运动时是否仍像真实身体 | 使用可编辑骨架、关节蒙皮和动作片段；校正手指、肩肘、髋膝踝的变形，并把根节点位移与支撑脚约束一起处理。 | 从正侧面播放完整动作，再慢放看手腕、脚底和物体接触；静帧漂亮、脚底高度正确、时间可逆都不能单独证明动作合格。 |
| 移动中会否卡顿、跳模 | 按可见距离供给材质与模型，检查远近版本的轮廓和 UV。对固定照明烘焙，对近处水面限定反射范围；验证资源预热与释放。 | 在约定硬件上测首次转身及连续行走的帧时，记下测试条件、新上传与着色器编译。桌面触屏模拟与真机测量分别记录。 |

## 人物从模型到动作

先用一个角色完成可播放的动作样板，再扩展到同类人物。生成模型的面数与贴图精度不代表它能自然运动。详细依据与《铅笔倒带》的接入问题见[人物动画调研](CHARACTER_ANIMATION_PIPELINE_RESEARCH.md)。

1. **准备可绑定的身体。** 采用中立 A/T 姿态，检查手指分离、腋下和胯下空间、关节周围拓扑及实际比例。保留合格的头部与材质；有问题的身体局部清理、重拓扑或重新生成。不要用大范围顶点拉伸把一个固定姿势强行改成完整肢体动作。
2. **绑骨并校正蒙皮。** 肩、肘、腕、手指、髋、膝、踝各有合适关节；自动权重是起点，需要用弯肘、抬臂、屈膝和握物姿势检查塌陷、拉丝与相邻肢体串动。高模可以把细节烘焙到适于变形的网格，保留原件与可编辑工程。
3. **用动作片段驱动全身。** 以有来源和许可记录的动捕或关键帧动作重定向，修正体型差异。行走应有重心、髋部、膝踝和反向摆臂；位移与步长配合，支撑阶段锁定脚的世界位置。投篮需统一下肢发力、双手握球、出手帧与手腕跟随，不能只检查球距一个手部采样点的距离。
4. **烘焙后接入可逆时间线。** 对短的固定演出，先在制作工具中解算脚与手的约束，再烘焙根节点和骨骼轨道。导出 GLB 的 skin、权重、关节层级和 animation 均须保留；运行时按绝对时间采样，检查任意跳时、倒放与重复播放的一致性。静态道具的网格合并、逐轴归一化路径不能直接套到绑定人物上。

动作目标须保存连续影片，覆盖正常速度和 0.25 倍慢放、正面和侧面，以及用户能走到的最近距离。至少逐项复核：

- 支撑脚在世界平面上是否滑动，脚跟到脚尖的正常滚动与滑步分开记录；建议本项目先以明确接触点在单次支撑期漂移不超过 1 cm 作为样板数值门槛，之后按实机比例复核。此数值是项目建议，不是行业统一标准。
- 不能仅测标记过的支撑窗：慢走的完整时间段至少一只实际鞋底应贴近地面，交接帧和最终定格也要检查；跳跃动作单独标记允许腾空的阶段。按最终导出后的插值结果测整双鞋，不能只用脚骨原点或一个挑选过的鞋底点代替。
- 手腕、前臂、肩肘、膝踝是否异常伸长、塌陷或穿插；网格边长异常可作诊断信号，不能替代形体看片。
- 分件头部与身体必须在最终骨架、材质和光照下近看颈部接合；裁切锯齿、重叠表面和肤色断层不能因静态挂点对齐而略过。包体、肩带等分件保留轮廓与 UV，按正确身体部位绑定，不应被腿部权重牵扯。
- 双手与球等道具的接触、松手和随动是否连续；脚底接触与球的位置要在同一完整时间段检查。松手后仍须复核肩、肘、腕的配合，避免手腕已下压、肘部仍停在持球位置而反折；持球间隙通过不能替代出手和收势验收。
- 正播、倒播与随机跳到同一时间是否得到相同骨骼、根节点和道具状态；桌面与触屏的导出副本分别检查。

缺少完整运动证据或已有明确形变、滑步问题时，人物动作项记录 `fix`。交互 QA 通过仅证明控制流程可用，不能替代动作验收。

## 从简报到逐版复核

在 `story` 使用的 JSON 中，每个画质目标写上唯一的 `id`、可复现的机位或动作 `view`、预期看到的结果 `expect`。例如下面这项来自小镇的水面。室内题材可以改为“从柜台左侧走向右侧，后排陈设依次从立柱后显露”。选本作品能观察的现象即可。

```json
{
  "artTargets": [{
    "id": "puddle-reflection",
    "view": "在茶楼前同一个水坑旁横移，并转头看向水面。",
    "expect": "对街屋檐的倒影随视角改变，水岸仍贴在原来的坑边。"
  }]
}
```

`init` 和 `story` 都会给出本指南路径。`story` 返回已登记的目标。`build` 将目标随场景写入不可变版本。技术 QA 通过后，agent 打开实机截图或影片，用约定的相机、视场和曝光比较；运动或视差目标用两处可复现机位或连续片段。小镇的正常 QA 会为桥下路面、茶楼水坑及横移后的同一处积水留图。

```sh
./photo-demo/universe sole-city art-review
./photo-demo/universe sole-city art-review --record review.json
```

第一条命令返回当前版本、证据目录、已有记录、`art_targets` 和尚未检查的 `missing_targets`。第二条保存本次完整复核快照。续写时保留仍适用的同版本检查，新增或替换本轮结论。下面是一项检查的写法，`version` 使用第一条命令的实际返回值，文件名取本次 QA 的实机证据。

```json
{
  "version": "<当前版本>",
  "checks": [{
    "target": "puddle-reflection",
    "subject": "茶楼前井盖旁的水面",
    "evidence": ["desktop-teahouse-water.jpg", "desktop-teahouse-water-sidestep.jpg"],
    "verdict": "pass",
    "note": "横移后檐柱在水中的位置改变，仍能用同一井盖和坑沿辨认这片积水。"
  }]
}
```

有明确缺陷时记 `fix` 并写出复现动作，读取 `next=repair` 后进入返修；遗漏目标时会返回 `inspect_keyframes`。每个已声明目标都有通过结论、版本证据有效、技术 QA 通过后才返回 `reviewed`。无目标的旧简报沿用已有复核记录。新版本重新收集证据，前一版本的结论可作对照。这个状态说明该版覆盖了作品约定的画面，视觉判断仍由实际看片的人或 agent 作出。

## 从完成制作到正式上线

模型或画面验收后，仍需把整个作品打包成不可变候选，执行[统一上线检查](../deploy/QUALITY.md)。从真实相簿入口验证共用 UI、加载进度、冷启动与重访耗时、手机横竖屏、平台徽标遮挡、失败重试，再复核六张实际截图。按照[作品上架流程](../deploy/README.md#作品上架流程)登记视觉记录并推广版本；任一检查未通过，不更新正式版本号。模型替换也必须重跑，不能用模型本身的质量代替播放器与加载体验的验收。
