# 背面宇宙 · 桌上的假期

4.5秒从书桌照片进入三维空间，实际绕到电脑、书本与杯子背后，发现栈道相连的微缩海岸。可在任意位置停留和反向返回。

## 运行

```sh
npm run dev
npm run check
```

优先核对：[原照机位的实景还原](http://127.0.0.1:9988/?view=room&v=desk-details)。右下角切换原照片与三维，关闭景观、转场与景深模糊。绕行体验：[localhost:9988](http://127.0.0.1:9988/?v=continuous-handoff)。校准几何对照版：[laptop=calibrated](http://127.0.0.1:9988/?laptop=calibrated)。原生HTML/CSS/JavaScript和本地Three.js，无CDN。PORT环境变量可覆盖9988。本轮只更新本地，旧云端站点不是当前结果。

## 当前实现

- 原JPEG保留。初始DA3深度照片只在标定相机原点被观察；局部柔焦交接在30%完成，34%后才移动和绕行，避免提前移动拉伸单目深度边缘。
- 移除整场照片投影。桌面/窗帘先用本机SAM 2.1分割去掉前景，再做局部填补并绑定表面UV，避免重复物件轮廓投到背景。
- 电脑先以矩形、共用铰链和外屏1.55比例约束拟合原图，角点RMS3.23像素。当前默认使用SAM分割原电脑后生成的Hi3D模型，再依据上述几何参照匹配尺寸、朝向和位置。该误差是校准几何的误差，不是对生成网格误差的承诺。
- Hi3D新电脑模型为V3高质、PBR、私有，用户明确批准45积分；任务 `18ce0611df1a4972b48d0389b88ae32e` 已完成，只提交一次。原件约47MB保存在evidence，网页版本80,000三角面、3,556,900字节。[原模型查看](https://www.hi3d.cn/3d-model/18ce0611df1a4972b48d0389b88ae32e)。
- 电脑校准对照版保留原屏幕和键盘固定UV。两版书封均来自原图；杯子重拟合高度/半径，并采用深蓝釉面、浅色内壁和低于杯沿的深色咖啡。室内雾已删除，避免相机远近导致表面不合理泛灰；使用大面积窗光环境和台灯暖光。
- 固定后侧海岸连接电脑背壳、书页台地和杯后开口。海面、船和棕榈有独立可暂停动态。
- 椅子、右侧蘑菇台灯、书上叠页物件现默认使用真实SAM 2.1局部遮罩生成的Hi3D独立模型。每件45积分，本轮已确认并实际扣费135积分。原件约49.6/47.1/47.3MB；网页版本分别18万/约5万/4万三角面，约7.20/1.69/1.62MB。右侧开放柜和木色抽屉柜保留人工补建。
- 三件模型用原照相机与SAM轮廓拟合均匀缩放、位置和水平朝向，并约束椅脚/灯座/纸页分别接触地面/侧桌/书封。整个绕行中姿态固定；纸页的错误金属度已归零，台灯灰色灯罩与暖色灯杆分别处理，小屋位置为新物件留出空间。`?furniture=calibrated`保留旧程序几何对照。

## 交互和验证

拖动、滚轮、双指缩放或底部滑块控制同一路径；方向键前后、Home返回、End抵达、空格/Enter播放暂停。手动输入可接管自动播放。减少动态偏好下自动移动直接抵达，环境默认暂停；声音默认关闭。

`npm run check`验证JS语法、连续可逆时间线、真实180°相机终点、照片退出、矩形及铰链约束、角点误差、交接前相机不移动和必需纹理。新模型集成记录为 `evidence/hi3d-integrated-qa.json`：1440×900和390×844，含用户指出的75°状态，Hi3D确实加载、80,000三角面、无浏览器错误、无溢出、暂停和返回正常。使用Apple M2 Max Metal，手机视口不是手机真机性能测试。

家具修正记录为 `evidence/furniture-v2-qa.json` 和同名前缀截图：原照片相机的纯三维对照，以及桌面/手机的交接后、75°、180°视角。检查椅子面向桌面、纸页位置与旋转全程不变、柜体始终可见，无浏览器错误。原照相机对照通过测试路由固定相机，不改变产品镜头。椅子锚点RMS约8.80像素仅评价手工标注点，不代表完整椅子轮廓或材质与照片一致。

## 分割与资产复现

本次实际运行的是官方 **SAM 2.1 Hiera Tiny**（Apple MPS），不是SAM 3。模型、照片哈希、遮罩提示和后处理记录在 `dist/assets/objects/manifest.json`。

1. `scripts/fit-laptop.py` / `scripts/fit-cup.py`：numpy/scipy约束拟合。
2. `scripts/segment-objects.py` / `scripts/segment-tabletop.py --checkpoint <SAM2.1权重>`：真实模型分割。
3. `scripts/bake-room-surfaces.py`：Pillow/OpenCV整流纹理，依据遮罩补绘遮挡区。
4. `scripts/optimize-laptop.py`：Blender优化已下载的Hi3D GLB。
5. `scripts/fit-furniture.py` / `scripts/bake-furniture-textures.py`：旧家具锚点拟合与纸面/木纹的原图采样。
6. `scripts/prepare-furniture-inputs.py`：SAM局部裁切推理、遮罩清理与三张独立Hi3D输入。
7. `scripts/optimize-furniture.py`：Blender减面、贴图优化、Y-up几何采样；`scripts/fit-generated-furniture.py`：真实模型的轮廓拟合。

核心模块：`journey.js`负责路径，`seam.js`负责柔焦交接，`photographic-material.js`负责固定原图材质，`room.js`负责校准物件，`furniture.js`负责右柜和旧家具回退，`generated-furniture.js`负责新家具注册及材质校正，`laptop-model.js`负责Hi3D姿态注册与回退，`desk-holiday.js`负责共同海岸。

## 边界与后续方案

这次修复了非正交电脑几何、全局重复投影、提前移动深度照片、椅子反向、纸页变形和右柜缺失等具体问题；背景补绘、椅子曲面轮廓和小物件隐藏面等仍有近似，不能声称所有角度已照片级一致。新家具的隐藏面由Hi3D推测，其余家具隐藏面由人工补建；单张照片无法核实这些区域。Hi3D屏幕文字与细节也由模型生成，不能等同原图像素。原图的书封被遮挡、杯子分辨率很低；分割无法恢复缺失信息。

[SAM 3](https://github.com/facebookresearch/sam3)提供分割；[SAM 3D Objects](https://github.com/facebookresearch/sam-3d-objects)另能预测形状、纹理及场景姿态。后者官方部署需要Linux/NVIDIA至少32GB和模型访问授权，见[官方设置](https://github.com/facebookresearch/sam-3d-objects/blob/main/doc/setup.md)。Hi3D可接收分割后的物件，但独立模型仍需尺度、朝向、相机和光照对齐。本次没有申请SAM3权重或额外购买服务。

## 三件家具集成验证（0.7）

记录为 `evidence/generated-furniture-v2-qa.json`：原照相机对照、1440×900和390×844视口的交接后/75°/180°/逆向/返回，以及固定机位对照，共13个记录。三件模型确实加载，接触面误差小于0.005场景单位、姿态在进退中不变、无浏览器错误和横向溢出。对照模式另由 `evidence/reference-room-qa.json` 验证照片切换、相机不移动、无景观和无后处理模糊。手机视口不代表手机真机性能。

原模型：[椅子](https://www.hi3d.cn/3d-model/1ada5a4bc5c442e4a9c3c9a320d983c3)、[台灯](https://www.hi3d.cn/3d-model/022d44d4f26b4a28b727d46b3d452754)、[纸页物件](https://www.hi3d.cn/3d-model/e6c8e52ad8c24294811ad9e4130150c6)。这些页面显示原始生成材质，网页场景另做了上述材质修正。任务均成功，只各提交一次；不得重复生成。本轮仅更新本地9988。


## 桌面和小物件修正（0.8）

桌面暗缝来自误采入顶面贴图的桌沿下方暗部。640个向下的网格采样均有命中，没有几何孔洞。现在仅在SAM桌面内部、排除物件与边沿后拟合平滑明暗；`scripts/check-desk-surface.py`验证前缘与内部的亮度比至少为0.8，原贴图为0.641，修正后为0.867。此方法补全均匀哑光桌面，不恢复被遮挡的原始像素。

`desk-details.js`重做长臂灯的双连杆、关节、两段弹簧、线缆与倾斜灯头；灯臂在绕行中保持存在。手机采用原照位置与方向、圆角实体和三枚镜头。耳机采用分开的厚耳罩、软垫和抬起的折叠头梁，连接杆终止在耳罩边缘。手机和耳罩可见面使用固定原图UV；橙色书封经SAM 2.1耳机遮罩去遮挡并重新映射。右侧Hi3D台灯修正过暗的金属反照率与粗糙度，保留暖色灯杆。没有提交新生成任务或新增费用。

复现：先运行现有桌面/物件分割，再使用含SAM2、torch、OpenCV、Pillow和numpy的Python环境运行 `scripts/prepare-desk-details.py`（本机checkpoint在脚本中）；输出纹理及 `desk-details-fit.json`。随后运行桌面回归检查和 `npm run check`。

视觉与功能记录：`evidence/detail-fixes/v2-qa.json`及同目录截图，包含1320×1739原照机位、1440×900和390×844、75°/180°/逆向/返回，共13个状态。纹理与几何均为本地修正，不能等同自动获得照片级全视角实景。


## 连续交接（0.9，以本节参数为准）

前两秒先加速聚焦桌面，再通过短暂的局部失焦完成照片交接。构图用一条世界空间视野高度曲线控制，FOV由距离反推；取消原30%–34%的静止空档。23%–39%完成照片交接（约1.04–1.76秒），在此之前相机保持原拍摄位置，只有转向和光学构图变化，避免拉伸单目照片。39%起真实绕行并靠近，保持4.5秒和180°终点。

交界的双源混合区缩至12 CSS像素，局部柔焦带42像素；前景桌面保持聚焦，外围按深度失焦。模糊使用HDR颜色目标的预滤波mipmap连续采样，替换原25个间隔较大的采样点，避免高反差边缘呈现多层复制轮廓。原照片曝光不再叠加暖色亮带。

景观不按阈值整组突然显示。交接结束后复用照片渲染目标，分别捕获同一机位的实景与含景观场景，按世界X方向从电脑后方到书本/杯子逐段合成。电脑和杯子的遮挡仍由真实深度测试决定；新景观和阴影随显露量连续进入。部分显露段需要两次三维渲染，完整显露后恢复一次。两份静态阴影图预热缓存，正反向使用相同阴影，避免历史帧影响。叶片/海水仍有动态，阴影使用静态近似。

检查：`npm run check`覆盖无停顿、单调构图、原拍摄位置保持、可逆轨道和连续揭示。`node scripts/check-transition-browser.cjs filtered`覆盖桌面/手机视口的26个采样状态，正反相机完全相同；暂停环境动态后截图差异不得超过单通道1/255舍入。另检查拖动接管、播放暂停、返回原照片、固定机位对照及减少动态偏好。记录在 `evidence/transition/filtered-qa.json`。该像素一致性证明反向稳定，不代表照片与生成网格完全一致。

仍可见原照片与生成屏幕/杯面材质和细节差异；本轮集中于连续性和局部交界，不修改已接受的桌面物件，不新增Hi3D费用。仅本地9988，旧云端站点未更新。
