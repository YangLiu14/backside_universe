# Marble 实景重建与实体融合：流程参考

整理日期：2026-11-04。适用于后续编写「照片 → Marble 场景 → 校准实体 → 建模世界」skill 时的流程、排错和验收设计。这是当前书桌案例的经验记录，尚未封装成通用 skill。

遇到生成房间的原图对齐、物件替换、重影/接缝修复或绕行路径问题时，从本文进入；API 接入细节看 [MARBLE.md](MARBLE.md)，首轮融合看 [MARBLE_HYBRID.md](MARBLE_HYBRID.md)，最终修复与探索镜头看 [MARBLE_REFINED.md](MARBLE_REFINED.md)。精确参数以各页 `assets/scene.json` 和构建脚本为准。

## 本轮结论与产品边界

用户认可融合修正版作为后续基础。对这张照片，Marble 的房间和桌面在绕行时比前几种试验更完整，但它会改写电脑、杯子和书上小物件的形状。保留房间的 Gaussian、替换关键物件、固定原照纹理、重建共同桌面支撑，取得了比单独调整相机更有效的改善。这是单个案例的产品判断，没有跨输入的模型排名结论。

下一阶段采用 **原照片 → Marble 实景段 → 建模度假世界**。正面和绕行初段保留实景感，继续向后时交给可控的建模场景。桌后未观测空洞成为选择交接区间的依据；本轮不再以补齐全部背面为前置目标。现有验证页独立保留，交接尚未实现。

后续交接应满足：

1. 先把建模场景的桌面、电脑、杯子、书本及度假物件注册到同一空间。关键实体能共用时，在交接两侧保持同一份几何与变换。
2. 镜头位置、朝向、投影随同一条连续时间线计算；一边绕行，一边交接。不能在换场景时换机位、停下来淡化，或重新从模型默认角度开始。
3. 逐帧选定双方都能承接的角度区间，在桌后空洞占据注意力前完成交接。**±12° 是局部验收范围，±120° 是当前探索范围，都不是已确认的转场触发阈值。**
4. 先处理几何遮挡与轮廓一致性，再把柔焦用于短暂的虚实交界。大面积同时显示错位的两套物件会再次形成重影；模糊不能替代注册。
5. 度假世界随绕行和遮挡关系逐步出现。正向、反向到达同一进度必须得到相同镜头、显隐和混合权重，避免单向触发事件造成跳变。

以上是下一阶段的实现约束，不是本轮已通过的转场验收。

## 版本和职责

这轮由 image-blaster 调研转入直接调用 World Labs API：先用完整原照生成房间，再在已注册的空间里修复关键物件。这样能分别判断世界生成、原图配准和实体修复的收益，而无需把默认物件摆放误差混入模型评估。最初的±12°限制来自我们的验证页，并非 Marble 渲染器只能观察这么小的角度。

| 保留版本 | 负责验证 | 从该阶段得到的经验 |
| --- | --- | --- |
| `marble-lab` | 完整原照的一次 Marble 1.1 输出、机位注册、±12° | 先校相机再评估生成内容；空间连续不等于物件保真 |
| `marble-hybrid-lab` | 房间 Gaussian + 电脑/杯子/书/纸页实体 + 固定照片投影 | 替换必须同时处理旧前景、接触面和源视角可见性 |
| `marble-refined-lab` | 杯柄、书边、连续桌面、近桌路径和自由观察 | 支持纹理也会生成重影；镜头路径决定哪些缺陷会暴露 |

原始生成只有一次，实际 1,580 credits，192 万 Gaussian；后两轮本地处理没有新增付费生成，也未使用 3090。世界 ID、资产哈希和参数在 [原始场景记录](../dist/marble-lab/assets/scene.json) 中。新机器优先恢复资产及任务记录，再续接已有任务；不要把重新付费生成作为恢复方式。

## 可复用的执行流程

### 1. 固定输入与基线

记录完整原照的尺寸、SHA256、使用范围；保存现有运行文件的哈希快照，给新试验独立目录。准备照片、已有 SAM 遮罩、校准网格/Hi3D 资产、旧相机内参及它们的来源说明。

生成前确认本次收费授权和实际报价。key 只在服务端环境或 `photo-demo/.env.local` 中读取；预览请求不能携带可见密钥，网页只加载下载后的本地资产。服务条款、价格和 API 行为需在未来调用时重新核实，本案例不是永久授权或定价依据。

**完成条件：**输入可由哈希定位，基线可恢复；已有生成任务与新生成被明确区分。

### 2. 一次生成，持久化续接

`marble-world.py` 固定本案例原图、模型和私有权限；先检查余额，以进程锁防并发，在收费 POST 之前写入提交状态，再保存 operation ID。网络中断后续接同一 operation。若提交结果未知，先找回任务 ID；不能自动重复 POST。

保存原始 SPZ、备用规格、全景及返回的碰撞网格，记录哈希和坐标语义。完整响应、下载地址和任务状态在忽略的 `evidence/` 中；公开的 `scene.json` 只含必要元数据。

**完成条件：**真实下载成功、哈希可复查、费用与任务 ID 有记录。等待页能打开不等于已生成，更不等于画质通过。

### 3. 统一坐标，注册原照片机位

本案例先按返回的 `metric_scale_factor` 和 `ground_plane_offset` 处理 Marble 坐标，再转换 OpenCV/Three.js 轴向。实际等价变换为：

```text
world = raw_position × scale × [1, -1, -1] + [0, ground_offset, 0]
```

该公式用于本次已核对的坐标约定；不要照搬旧 InfiniSplat 的尺度、内参或绕行中心。

用共同特征拟合朝向/FOV，再借 Gaussian 射线深度拟合相机位置。多处锚点一起检查：屏幕、底座、书、杯子和桌沿。对齐流程只改相机，不对照片作二维扭曲。锁定源相机和裁切后再检查新视角。

**完成条件：**保存机位和残差，并目视区分“构图误差”和“模型改写了物体”。本例 128 个共同特征的中位误差约 4.90 px（630×830），只评价该匹配集；不同匹配集的残差不能直接比较，更不能证明隐藏面正确。

### 4. 替换实体，同时处理它的背景与支撑

先在相同机位保留 A/B 基线。分割提供可见轮廓，已有模型提供几何；二者都不能直接确定 Marble 世界中的深度和接触位置。

- 从可信桌面点拟合共同支撑面，再将旧模型注册到 Marble。单视图中可以保留原照射线、重新分配深度，使轮廓延续已有校准；应注明这是单视图拟合，不是实测刚体恢复。
- 电脑、杯子、书本和纸页一起检查接触高度。纸页模型替换后若原书面不同步，仍会悬空或穿桌。
- 删除旧物件时联合使用屏幕轮廓、深度、离桌高度和 Gaussian 尺度；只用二维遮罩会误删后面的窗帘/桌面。对衍生 SPZ 只清零目标 opacity，并验证保留点的属性字节不变。
- 原照纹理固定在源相机坐标，以源深度可见性和物件遮罩控制投影。新相机仅用于观察，不能驱动纹理漂移。源机位没看到的表面使用明确标注的近似材质。
- 实体与背景必须共享深度遮挡。补面用固定三维表面填充，避免在屏幕上叠一张底图。

**完成条件：**0° 和 ±12° 同机位检查无旧物件副本，接触高度合理、轮廓不跳；关闭实体/照片纹理后能解释每一层的来源。投影转换误差接近零只说明保留旧配准，不代表真实重建误差接近零。

### 5. 分开修复几何接缝、颜色接缝和采样问题

先定位缺陷所在层，再改对应构建环节；以同角度、同裁切的图做对照。桌面内部保持实体接触平面，边界向已观察到的 Marble 高度接合。纹理从同一机位的 Marble 渲染取色，排除旧前景、桌沿和阴影污染，再对未知区做平滑延展。

本例最终将局部 Gaussian 支持片改为连续、不透明的桌面网格；杯釉和书封仅从有效内域取色并向边缘扩展。原照片已含光照，投影材质需避免再叠一套不一致的强光照。观察大角度时仍要说明未见侧面的材质是估计。

**完成条件：**关掉实体仍没有平面“旧书/旧杯”；边界在两侧角度都接合；修复没有扩大到窗帘等背景。为已复现的污染加入具体回归检查，不把颜色计数当成全场景质量指标。

### 6. 设计可观察的镜头路径

先保留±12°的原轨道，用于稳定对照。大角度路径根据空间收紧半径并连续靠近物件；沿原房间半径直接转到90°–180°会穿墙。自由转头和位移应分开，避免用户每次拖动都绕大圈。

本例引导范围到±120°，自由移动只有房间大致边界，并非精确碰撞。允许相机移动到某个位置，不代表该位置有可靠几何；后续产品路径优先连接建模世界，而非无限扩大未经观测的实景视角。

**完成条件：**检查连续采样、往返到同一角度的确定性、A/B相机矩阵一致；实际操作拖动、平移、滚轮、键盘和复位。连续性测试不等于帧率测试，也不等于各机位画质通过。

## 排错索引：现象 → 定位 → 修复

| 现象 | 定位证据 | 本例采用的修复 / 避免重复的失败尝试 |
| --- | --- | --- |
| 首帧抬头、布局整体偏移 | 多处锚点同方向错位，默认机位是全景朝向 | 先注册相机；相机对齐后仍变形的杯子需替换实体 |
| 纸页偏金、书后仍有残片 | 检查对应 Gaussian 的深度，残片不属于新模型纹理 | 调整局部清理深度；未重新生成 Hi3D 模型 |
| 书页倾斜穿桌 | 直接仿射映射后，纸页与书本支撑高度不同 | 保留源射线，统一书/纸页高度映射 |
| 倾斜书面出现条纹 | 源深度可见性采用最近邻采样 | 改用线性深度采样及保守边界判断 |
| 书下三角透明缺口 | 平面拟合用的内缩区域被误用为完整补面边界 | 分离“可靠拟合区”和“需要覆盖区”，补足后沿 |
| 桌面补片灰棕、边界突兀 | 取色样本包含棕色桌沿下表面 | 只从内缩、明亮、近中性的桌面取色，边界匹配原渲染 |
| +12°出现扁平的蓝色书本副本 | 关闭实体后副本仍在；支持纹理内有旧书颜色 | 边界混色也排除前景，蓝色污染计数从2237降至0；另清理局部蓝色残点 |
| 清理书边后窗帘出现黑洞 | 扩大深度范围误选背景点 | 撤回过宽清理，按近桌高度/空间范围限制；不能只按颜色全局删除 |
| 杯柄混入背景、书封锯齿色边 | 纹理轮廓外取到了背景 | 有效内域取样并延展边缘、校准杯柄高度；开启网格抗锯齿 |
| 窄屏 Gaussian 有额外采样洞 | 禁用协方差抗锯齿后随视口出现 | 保留 Spark 标准 `blurAmount: 0.3`；它是抗锯齿，不是景深遮掩 |
| 90°–180°画面穿墙 | 相机仍沿原始房间大半径 | 采用近桌路径；未将贴窗帘的180°作为通过机位 |
| 延长隐藏桌面在120°形成突出片 | 源视角轮廓外推缺乏真实深度约束 | 撤回该延伸；后续由完整建模世界承接 |
| 局部截图指标异常 | 此次工具的 clip 忽略 x/y，只采用宽高 | 保存全页截图和 DOM 矩形再裁切；核对裁切图后才计算指标 |

| 镜头算法 | 2,401个角度采样，±12°与旧轨道一致，往返确定；验证连续性，不证明无碰撞、稳定帧率或全视角保真 |

## 提炼为 skill 时的边界

可复用的是：输入与费用记录、可恢复任务、坐标注册、分层诊断、局部有界删除、共同支撑、源视角可见性、同机位A/B、确定性镜头和证据分层。

当前仍是案例专用的部分：照片尺寸/哈希、手工多边形和 SAM 轮廓、深度/颜色阈值、相机内参、桌面平面、杯柄提升量、纸页高度映射和房间边界。更换照片或生成结果时需重新估计并验收。SPZ编辑器只接受本次观测到的 **v2 / SH degree 0 / flags 0**，不能包装成任意SPZ通用工具。

未来 skill 的输入契约至少应区分“生成新世界”“恢复已有世界”“局部修复”“交接到建模世界”；输出应携带源资产哈希、参数、独立对照入口、实际完成的检查和仍未观测的范围。先用第二张照片验证这些步骤，再决定哪些参数能自动化。

参考依据：[World Labs 坐标与SPZ渲染](https://docs.worldlabs.ai/api/rendering-spz)、[Spark 渲染和抗锯齿](https://sparkjs.dev/docs/spark-renderer/)、[Niantic SPZ格式](https://github.com/nianticlabs/spz)。本文描述2026-11-04这次运行的行为；未来接入版本变化时重新核对格式和服务约定。
