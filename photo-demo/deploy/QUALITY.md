# 统一上线检查

每个新作品、每次模型替换或播放器修改，先打包为不可变候选，再从真实相簿入口检查。`review-release.py` 的证据是上线依据；单件 `qa` 不能替代。整个场景中的模型由该场景共同验收，模型源文件归档与 Hi3D 来源检查仍走制作流程。

## UI 与交互契约

使用 `dist/cinema/premiere.css` 的当前文件：近黑舞台、宋体片名、暖金主按钮、统一页眉、返回相簿、时间轴和辅助操作。允许场景布局文件调整舞台尺寸和专属交互，公共控件沿用设计变量。HTML 中 `body.premiere[data-player-ui="premiere-v1"]` 标明契约；仅添加标记不够，自动检查还会比较样式文件、实际颜色、触控尺寸和点击是否被遮挡。

通用控件包含 `data-album-back`、`data-film-start`、`data-film-home`、`data-film-explore`。舞台使用 `#stage`、原照使用 `#photo`；可交互时设置 `data-ready="true"`，探索时设置 `data-walk`。特殊故事可以保留额外操作，但不能省略返回、暂停和加载反馈。键鼠与真实触控输入另由作品自己的 QA 检查。

## 加载契约

首屏先显示原照和加载反馈。复用 `cinema/loading.js` 与 `data-film-loading` 结构，包含有无障碍名称的 `role="progressbar"`、当前阶段、已等待时间和 `data-load-retry`。未就绪的操作保持禁用，返回相簿始终可用。

- 总量已知时只报告实际完成数量或传输字节；总量未知或正在解码、编译光影时用不定进度。
- 模型计数完成不代表作品可操作；首次画面绘制与预热完成后才关闭加载面板。
- 失败保留原照，用日常语言给出重试，不把技术错误堆给观众。重试必须真的恢复到可播放。
- `data-film-critical` 指向包内实际启动资源。检查器将它延迟、返回 503，再恢复，用来验证慢网和失败流程。
- 高精度资源可按距离加载；必须保留合理远景，并由场景 QA 验证近景切换、失败反馈和画面质量。

## 自动验收

唯一阈值来源为 [quality-policy.json](quality-policy.json)。当前采用：

| 项目 | 上线门槛 |
|---|---|
| 桌面冷启动 | Chromium，1280×800，50 Mbps、80 ms RTT，首次可操作 ≤40 秒 |
| 触屏冷启动 | Chromium 触屏模拟，390×844，CPU 2 倍节流，同网络，≤60 秒 |
| 原照出现 | 进入后 ≤2.5 秒 |
| 启动下载量 | ≤160 MiB，记录实际冷启动传输量 |
| 同页重进 | ≤1.5 秒，保留进度，不重复取资源 |
| 加载体验 | 延迟启动资源 5 秒：原照、阶段和进度条可见，能返回 |
| 失败恢复 | 关键资源 503 后 ≤8 秒出现重试；恢复后能播放 |
| 布局 | 中英文、手机横竖屏、44 px 触控范围、无横向溢出 |
| 遮挡 | 父相簿及子播放器均模拟 202×64 px 平台徽标，操作必须能点击 |
| 后台 | 返回相簿后进度不走，作品自身 QA 另验声音与漫游暂停 |

这些是当前重型三维作品的发布上限，需持续压低，并非推荐下载体积或真实手机/公网 CDN 的速度承诺。报告必须保留设备、网络、CPU、实际耗时和下载量；不能只写“加载很快”。调整门槛需要写明原因，改规则后所有新候选报告重新执行。真实手机和公网发布后的检查单独记录，权限或网络受阻时不能标成通过。

## 视觉复核与推广

检查器保存六张图：`desktop-ready`、`desktop-explore`、`touch-ready`、`touch-landscape`、`slow-loading`、`load-error`。逐张查看，确认首映风格、照片比例、文字层级、可读性、控件位置和加载反馈。技术测试通过不等于视觉通过。

视觉记录使用下面格式，为上述六项各写一条实际观察；不要根据文件名自动生成“通过”。

```json
{"checks":[{"screen":"desktop-ready","verdict":"pass","note":"片名与暖金播放键沿用首映样式；时间轴未遮挡原照。"}]}
```

按[发布流程](README.md#作品上架流程)执行 `review-visual` 和 `promote`。记录绑定候选版本、当前检查器/共享 UI/规则摘要、技术报告以及截图内容。修改源代码要重新打包；修改截图或规则后旧记录失效。`pack --record`、目录生成、导出与 ZIP 均受检查约束。`legacy-quality-pins.json` 是规则启用时的历史兼容清单，新增作品不得往里填版本来绕过检查。

## 发布后

只上传已验收的导出目录。确认平台发布成功后，从访客正式域名核对目录、封面、当前版本、模型请求和历史入口，再实测进入、返回和重访。首屏加载与近景资源均应可用。保留平台部署 ID、实际网址、验收设备及结果。失败时回滚到保留的版本；有阻塞时写明“尚未完成公网验收”，不以本地报告代替。
