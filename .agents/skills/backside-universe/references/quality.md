# 从故事动作到可验收的试玩

选定故事或收到返修后，先确定**观众在什么位置，要看到什么，做什么，怎样知道动作完成**。把答案落实到故事规格、机位和验收；不要把某件作品的模型数量、色温、镜头角度或天气当成新作品的默认值。

| 什么时候用 | 制作决定 | 完成的证据 |
| --- | --- | --- |
| 所有绕行 | 用同一进度求相机和投影，照片可用的视差决定交接角度。原照仍遮住画面时预绘正、背面和各自的灯光配置，准备贴图、网格和 Gaussian 排序后再让用户拖动。 | **新开页面**先走一次真实绕行，再截图或跳进度。交接时进度变化、视点也变化；记录帧间隔及首次 GPU 工作。倒拖同一进度应回到同一机位和投影。 |
| 能走入的内景 | 明确地板、墙、顶和开口怎样围合；从室内能看到的窗框、灯具和墙角要有厚度。按年代和地点选一两件可辨识的生活痕迹。给暖光找得到的光源，给窗外独立的光色、前后景和遮挡。 | 在入口、正常眼高和低处各看一遍；关掉标题仍能辨认空间和故事线索。将关键机位截图放在当前版本的 QA 目录，注明模拟设备。 |
| 走动、入座或调整眼高 | 为第一个实际落点构图，从近处遮挡物上方能看到故事目标；桌面坐标落在屏内不足以证明未被遮住。第一人称鼠标左拖向右/上应向右/上看；若有升降，右键上拖升、下拖降，保持水平位置和朝向。触屏走动/环顾与键盘另测。物件绕转模式与第一人称区分。 | 固定初始位置检查目标可见；实测四方向、原地升降、窄屏、退出后回到来时机位。每个新入口都试直接进入、返回、再次进入；状态与道具数量不能累积。 |
| 有相邻或活动的道具 | 需要独立剪影、材质或动作的主角拆成独立 Hi3D 分件；同一种物件可实例化。用实际网格定桌面/支撑面、脚底和可走范围，预留活动间隙。 | 在统一局部坐标检验实体接触与意外相交；可移动道具覆盖从收起到展开的整条路径，从可达低位或侧后方看片。直线平移可用下方的扫掠检查；旋转、变形、曲线路径应采样中间姿态或检查相应扫掠体。 |
| 故事需要雨、热气、风或空间声音 | 先确定作用位置与尺度（例如从热菜上方升起、落在窗上沿玻璃滑动），按内外光源及遮挡调整材质和声场；特效和配音不替代关键模型。 | 在**静止机位**截取有特效的局部，比较间隔两帧，排除镜头、字幕、背景动画导致的假阳性，再看运动是否发生在正确的表面；声音、静音和字幕分别试。 |
| 相簿或便携交付 | 复用现有放映厅的入口、返回与导航习惯；从共用首页点击进入，再退回、重访。修正进入播放器源码或打包输入。 | 检查实际服务地址、作品 ID 和交付包对应同一 release；若交付约定含短片/剧照，重录受影响部分。独立页跑通不能证明相簿卡片、便携包或公开站点已更新。 |

需要第一人称走动时，从模板的 `./room-walk.js` 导入 `createRoomWalk`。案例传入 `canStandAt(x,z)`、眼高范围与站/蹲高度；将摇杆和键盘交给 `update`，左拖交给 `dragLook`（用视口比例），右键竖拖只调用 `lift`，回到全景时清空按键。相机围绕展品近看时不启用走动；不要复用餐桌的碰撞坐标。

**可直接使用的检查**（路径相对项目根目录）：

- `photo-demo/pipeline/qa/orbit.cjs`：通用和专属播放器均由验收器先执行 `coldOrbit`，再复位到原照。专属 `check.cjs` 须同时导出 `orbit={range,turn,state,pose,handoff}` 与 `check(page,device,viewport,out,url,coldOrbit)`。range 是进度条 ID；turn 是可选的自动绕行按钮 ID；state 是读取进度 0–1 的函数名，pose 是其返回的机位数组字段，handoff 是这件作品的交接区间。默认检测静态网格画布 mesh，Gaussian 的动态排序不计入。帧时用于同机比较，没有跨设备硬判一个 FPS 数值。
- `photo-demo/pipeline/qa/clearance.cjs`：对存在对应家具的专属场景，给两边网格的组命名。导航**之前**调用 `observeScenes(page)`；在动作前用 `furnitureClearance(page,{obstacle,subjects,margin})` 取得包围盒；在完成姿态传入同一规格和初始包围盒检查整段直线平移。margin 用障碍物父级的单位。此保守检查包含包围盒里的空隙；合法嵌合件用分件或更贴身的检测体。
- `photo-demo/pipeline/qa/effects.cjs`：`changedPixels(page,readCameraMatrix,x,y,width,height)` 返回静止视角的局部变化像素数；由作品按画面选区域和阈值。`photo-demo/cases/grandmas-table/check.cjs` 是这三种检查和键鼠/触控、视线可见性联合验收的例子。
- 普通 `light/chime/turn` 故事走通用模板。需要走进空间、拉动实体或按地点改变天气等体验时，选用或实现专属 `experience` 和 `check.cjs`，再登记道具输入；填写故事字段本身不会生成这些玩法，也不会自动生成相簿卡片。

**返修从最小一层开始。** 先用同一位置、输入或冷启动路径在原版本复现，再改机位、摆位、控制或材质；只在轮廓或动作确实缺少几何时才启动新的 Hi3D 分件。保留改前证据，重用未变任务，重建后在新版本上复测原触发路径和返回路径。代理读图判断构图、时代感和穿帮，浏览器记录数值与截图；两者都完成后再对用户说“验收通过”。
